---

# Required Workflow

Every task MUST follow this workflow.

## Phase 1 — Understand

Before writing code:

* Understand the request.
* Read relevant files.
* Identify existing architecture.
* Identify reusable components.
* Understand dependencies.
* Detect constraints.

Never start coding immediately.

---

## Phase 2 — Plan

Before implementation explain:

* what will change
* why it should change
* affected files
* possible risks
* better alternatives if applicable

If the requested solution is poor, explain why.

Recommend a better solution before implementation.

---

## Phase 3 — Implement

Implementation should:

* be incremental
* avoid unrelated edits
* preserve existing functionality
* reuse existing components
* remain production ready

---

## Phase 4 — Review

After implementation verify:

* responsiveness
* accessibility
* performance
* animations
* TypeScript
* linting
* imports
* dead code
* bundle impact

Nothing is finished until reviewed.

# Design Rules

The design language should feel premium, minimal, technical, confident, modern, and high-end.

Avoid AI startup aesthetics, marketing websites, visual clutter, and animation overload.

Full specification: See DESIGN_SYSTEM.md

---

# Animation Philosophy

Animation exists only to guide attention, improve hierarchy, reinforce interaction, and improve perceived quality.

Never animate simply because something can move. Every animation must have a purpose.

Full specification: See ANIMATIONS.md

---

# Component Rules

Every component must be reusable, accessible, responsive, composable, typed, documented, and independent.

Reusable components are preferred over page-specific components.

Full registry: See COMPONENTS.md

---

# Code Standards

Prefer: Server Components, TypeScript, Tailwind, Design Tokens, Semantic HTML, ARIA, Reusable Hooks.

Avoid: magic numbers, duplicate logic, duplicate components, large files, deep prop drilling, unnecessary state, inline styles, unused imports.

Full architecture: See ARCHITECTURE.md

---

# Accessibility

Accessibility is mandatory. Every feature must support keyboard navigation, visible focus, screen readers, reduced motion, contrast compliance, and semantic structure.

Full specification: See ACCESSIBILITY.md

---

# Performance

Target Lighthouse 95+, fast LCP, low CLS, minimal JS, lazy loading, image optimization, and code splitting.

No unnecessary dependencies.

Full budget: See PERFORMANCE.md

---

# Mobile First

Every feature must work on mobile, tablet, desktop, and ultrawide.

Never optimize desktop first and ignore smaller devices.

Breakpoints: See DESIGN_SYSTEM.md § Responsive Breakpoints

---

# Content Rules

Show results, engineering, architecture, problem solving, decision making, and trade-offs.

Avoid long paragraphs. Prefer concise, high-impact content.

Full strategy: See CONTENT.md
